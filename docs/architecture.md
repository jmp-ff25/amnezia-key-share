# Архитектура KeyPort

```text
┌─────────┐  HTTPS  ┌────────────────────┐  private network  ┌───────────────┐
│ Browser │ ──────→ │ Caddy              │ ────────────────→ │ FastAPI       │
└─────────┘         │ TLS, headers, logs │                   │ auth, CSRF    │
                    └────────────────────┘                   └───────┬───────┘
                                                                     │ SQLAlchemy
                                                             ┌───────▼───────┐
                                                             │ SQLite volume │
                                                             └───────────────┘
```

## Границы безопасности

**Internet → Caddy.** Caddy завершает TLS, выставляет HSTS/CSP и другие security headers. Только 80/443 опубликованы. URI публичного доступа содержит секретный bearer-токен, поэтому access log Caddy и Uvicorn отключены по умолчанию. Метрики следует добавлять без записи URL path или тела запроса.

**Caddy → FastAPI.** Трафик идёт по приватной Docker network. Приложение доверяет proxy headers только внутри сети и проверяет Host по `TRUSTED_HOSTS`.

**Admin session.** Подписанная cookie содержит только признаки сессии и CSRF token, не пароль или VPN-ключ. HttpOnly задаётся middleware, `Secure` включается в production. Logout очищает cookie; смена `APP_SECRET_KEY` инвалидирует все сессии.

**Admin path.** Префикс панели задаётся `ADMIN_PATH` и генерируется CLI из криптографически случайного значения. Это снижает шум автоматического сканирования, но считается только дополнительной защитой: обязательными границами остаются Argon2id-аутентификация, rate limiting, CSRF и session cookie. Неизвестные пути, включая стандартный `/admin`, возвращают одинаковую HTML 404 без fingerprinting API.

**Public capability URL.** Токен имеет 256 бит энтропии. SHA-256 hash используется для lookup; обратимая копия токена позволяет администратору снова скопировать ссылку. Отключение сохраняет token/hash и позволяет вернуть прежний URL; отзыв удаляет оба; регенерация атомарно инвалидирует старую ссылку.

**Application → SQLite.** БД и backup содержат VPN-ключи plaintext и должны рассматриваться как секреты. Репозитории не возвращаются наружу как API-модели, SQL echo отключён. Будущее шифрование реализуется в сервисном/типовом слое: маршруты работают с plaintext только в памяти на границе отображения и изменения.

**Группы ключей.** `AccessEntry` владеет публичной ссылкой, статусом и описанием получателя. Один или несколько `AccessKey` хранят именованные VPN-ключи и порядок отображения. Удаление записи каскадно удаляет ключи; изменение состава группы не меняет публичную ссылку.

## Решения и trade-offs

### ADR-001: hash lookup и повторный показ публичного токена

Для быстрого lookup без сравнения plaintext хранится SHA-256 hash. Одновременно требование продукта предусматривает кнопку повторного копирования существующей ссылки, поэтому токен хранится и обратимо. В текущем MVP plaintext SQLite уже раскрывает VPN-ключи при компрометации, и отказ от повторного показа ссылки не улучшил бы итоговую границу безопасности. Будущее encryption-at-rest должно охватывать `vpn_key` и `public_token`; hash остаётся индексом.

### ADR-002: session auth без отдельного auth-фреймворка

Для одного администратора применены поддерживаемые `SessionMiddleware` Starlette и `argon2-cffi`. Полноценные account lifecycle/OAuth/roles отсутствуют намеренно. Это уменьшает поверхность атаки MVP, сохраняя зрелые криптографические примитивы.

### ADR-003: plaintext SQLite в MVP

Application-level encryption без внешнего управления ключами может создать ложную безопасность: секрет рядом с ciphertext не защищает компрометацию хоста. MVP полагается на защищённый volume, host hardening и encrypted off-host backups. Envelope encryption добавляется при появлении KMS/отдельного runtime secret и процедуры ротации.
